# SEO Audit — drranairfan.com — 2026-09-11

This is a point-in-time snapshot. Re-run the queries in "How this was produced"
periodically (see `CLAUDE.md`) and file a new dated audit rather than editing
this one.

## 0. The single most important finding

**The live site at `drranairfan.com` is WordPress + Elementor + RankMath.
This repository (`driv`, a Next.js 14 / Supabase app) is an unreleased
rebuild.** It is not deployed anywhere reachable at the production domain.
Confirmed by crawling `https://drranairfan.com/` directly: the response is
generated by `Elementor 4.2.4`, favicon served from `/wp-content/uploads/...`,
`og:image` served from `/wp-admin/admin-ajax.php?action=rank_math_overlay_thumb...`.

Practically, this means:
- Every "current ranking / current traffic" number below describes the
  **WordPress site**, not this codebase.
- Cutting this Next.js app over to `drranairfan.com` is itself the single
  biggest SEO event this project will have — bigger than any on-page fix.
  It needs a full URL-parity check and 301 redirect map before DNS/hosting
  ever points here. See Action Plan, P0.
- Until that cutover happens, work in this repo is **pre-launch technical
  SEO** (get it right before Google ever sees it) rather than "fix a live
  page."

## 1. What the live WordPress site already has going for it

- **Local Pack ranking**: for `hair transplant islamabad` (the head local
  keyword), "Dr. Rana Irfan" ranks **#4 in the Google local pack**, 4.8★,
  636 reviews — ahead of most competitors, behind one paid ad (Royce Clinic)
  and two organic listings (HairnHair 611 reviews, JJ Aesthetics 708
  reviews). This is a real, established Google Business Profile — a
  significant existing asset that a domain migration must not damage.
- On-page technical score from a live crawl: **96.34/100** (DataForSEO
  on-page checker), HTTPS, valid canonical, readable URL, has OG/Twitter
  tags, `og:image` present, CLS reported as 0.
- Title tag: *"Dr. Rana Irfan — Hair Transplant Surgeon in Islamabad,
  Pakistan | ABHRS"* — 71 characters (flagged `title_too_long`; Google
  typically truncates past ~60).
- Meta description present and reasonable (173 chars, also slightly long).
- H1/H2/H3 structure exists and is topically sane (FAQ section, testimonials
  section, "Understanding Hair Transplants" section already present — i.e.
  the WordPress site already does some of what this rebuild's `/faqs` and
  `/blog` are meant to do).
- A Google Search Console property is connected for this domain (see §4) —
  meaning historical indexing/query data exists and can be pulled once
  access is restored.

None of the above exists yet in this repository — it needs to be rebuilt
into the Next.js app (see §3) before cutover, or the site will launch with a
worse SEO footprint than what it's replacing.

## 3. This repository (the pre-launch rebuild) — technical/on-page findings

Reviewed: `src/app/layout.tsx`, `sitemap.ts`, `robots.ts`, `manifest.ts`,
`lib/constants.ts`, `procedures/[slug]/page.tsx`, `conditions/[slug]/page.tsx`,
`blog/[slug]/page.tsx`, `components/sections/*`, `components/layout/Footer.tsx`,
`supabase/migrations/001_initial.sql`.

**Structural positives already in place:**
- App Router `sitemap.ts` and `robots.ts` exist and are correctly wired
  (disallow `/admin/`, `/account/`, `/api/`; sitemap includes static pages +
  all `PROCEDURES`/`CONDITIONS` slugs).
- Fonts loaded via `next/font` (Inter + Playfair Display) — good for CWV,
  avoids render-blocking font requests and layout shift from web fonts.
- `sharp` is already a dependency — image optimization pipeline is available,
  just unused so far.
- Per-page `generateMetadata` exists for `/procedures/[slug]` and
  `/conditions/[slug]`.
- Supabase schema (`blog_posts`, `procedures`, `before_after_gallery`,
  `testimonials`) already has `seo_title`/`seo_description` columns and a
  `blog_status`/`procedure_status` publish workflow — the data model was
  designed with SEO in mind, it's just not wired up to the frontend yet.
- Footer carries a medical disclaimer and names the regulator (PMDC) — good
  E-E-A-T signal for a YMYL (health) site.

**Gaps found (all fixable in-repo, no external dependency):**

| # | Finding | File(s) | Why it matters |
|---|---|---|---|
| 1 | Zero structured data (JSON-LD) anywhere in the app | whole app | No `MedicalBusiness`/`Physician`/`MedicalProcedure`/`FAQPage`/`BreadcrumbList` schema → misses rich results, weaker entity signal to Google and AI answer engines (AEO/GEO) |
| 2 | No `alternates.canonical` set on any page's metadata | `layout.tsx`, all `page.tsx` | Relies on Next's implicit canonical only; explicit canonicals matter once query params, trailing slashes, or a WWW/non-WWW split exist |
| 3 | No per-page OG image; root `openGraph`/`twitter` blocks have no `images` field | `layout.tsx` | Shared links (WhatsApp is the site's primary CTA channel!) render with no preview image |
| 4 | Blog is a hardcoded object with **one** placeholder post; not reading from the `blog_posts` Supabase table that already exists | `src/app/blog/[slug]/page.tsx`, `src/app/blog/page.tsx` | Content/keyword strategy has nowhere to land — this is the main growth lever and it's disconnected from its own database |
| 5 | Every image in the UI is a CSS gradient placeholder — `BlogCard`, `BeforeAfterCard`, and (need to verify) hero/testimonial sections use no `<img>`/`next/image` at all | `components/sections/BlogCard.tsx`, `BeforeAfterCard.tsx` | Zero image SEO surface (no alt text, no file names, no image sitemap value) until real photography is added — and before/after galleries are one of the highest-converting asset types for this vertical |
| 6 | Footer links to `/privacy` and `/terms` — neither route exists (404) | `components/layout/Footer.tsx`, `src/app/` | Broken internal links on every page (footer is site-wide); missing privacy policy is also a trust/compliance gap for a health site collecting patient data (`consultation_leads`, `bookings` tables handle PII) |
| 7 | Footer social links (Instagram/Facebook/YouTube) point to `href="#"` | `components/layout/Footer.tsx` | Dead links; also a missed `sameAs` entity-linking opportunity for schema/off-page authority |
| 8 | `CLINIC_PHONE`, `CLINIC_EMAIL`, `CLINIC_ADDRESS`, `WHATSAPP_NUMBER` are all `// TODO` placeholders | `lib/constants.ts` | NAP (Name/Address/Phone) consistency is foundational to local SEO — can't ship local schema or GBP-matching data with placeholder values |
| 9 | Title in root metadata has no length guard; procedure/condition page titles are just the raw name with no keyword-optimized template | `layout.tsx`, `procedures/[slug]/page.tsx` | Live WP title is already 71 chars (too long); don't repeat that mistake in the rebuild |
| 10 | No analytics/conversion tracking of any kind (no GA4, no GTM, no server-side event logging beyond Supabase tables) | whole app | Impossible to measure "qualified organic leads" — the stated goal — without conversion tracking wired to the `consultation_leads`/`bookings` tables |
