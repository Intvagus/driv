# Audit — drranairfan.com, 2026-10-24: the site has been redesigned

Prompted by the user flagging a redesign. Re-crawled the live site
(`seo.on_page_instant_pages`, server-side DataForSEO crawl — bypasses this
environment's network block) across 9 key pages, plus a fresh Search
Console pull, to find out what actually changed. Short version: **this is
a real, mostly-good content redesign rolled out Oct 22–23, carrying one
new site-wide bug serious enough to offset a lot of the gain.**

## 2. The good news — this is a genuine content upgrade

Every redesigned procedure page now has a structure that's noticeably
stronger than what the Sept 11 baseline audit found, and addresses several
open tracker items directly:

- **Real FAQ/zero-click-resistant sections** on every procedure page
  ("FUE questions answered", "FUT questions answered", etc.), plus
  candidacy sections ("Am I a good candidate?" / "Likely a good candidate"
  / "May not suit you"), recovery timelines, and cost sections — this is
  close to what `OP-03`'s zero-click audit recommended (content a snippet
  can't reproduce).
- **Credentials threaded through, not just on one bio page**: "ABHRS
  certified & past president", "President HRSP & educator", "Surgeon-led
  consultation" appear as H3s on the FUE, Beard, and Eyebrow pages. This
  is substantially what `OP-07`'s rewrite and `OP-12`'s affiliations block
  were asking for — likely drawn from the same source material this
  engagement has been using (the clinic's official knowledge base), since
  the specific claims match almost verbatim.
- **Internal linking**: every procedure page now has "Explore other
  procedures" and "Start with a free hair analysis" sections — directly
  addresses the orphan-page risk `OP-02`/the Action Plan flagged.
- **The About page's new timeline** ("Graduated in medicine", "Uzma
  Medical Center opens", "First workshop in Pakistan", "Trains surgeons")
  matches the brand timeline in the clinic's own knowledge base closely.

**Re-verification needed, not assumed**: this is all from heading
structure (`htags`), not full body text — I can see the sections exist and
roughly what they cover, not the exact wording. Before marking `OP-01`,
`OP-07`, or `OP-12` fully resolved, someone should check the actual body
copy against those drafts' specific recommendations. Flagging this as
**substantially addressed, pending a content-level check** rather than
closing those rows outright.

## 3. The bad news — a new, site-wide title-tag bug

Every one of the 7 redesigned pages has a broken title tag using the raw,
lowercase, unformatted URL slug instead of a proper page title:

| Page | Current `<title>` |
|---|---|
| Homepage | `Dr Rana Irfan - Dr Rana Irfan - Hair Transplant Surgeon` (brand name literally duplicated — already logged as `OP-06`) |
| About | `about - Dr Rana Irfan - Hair Transplant Surgeon` |
| FUE | `fue hair transplant - Dr Rana Irfan - Hair Transplant Surgeon` |
| FUT | `fut-hair-transplant - Dr Rana Irfan - Hair Transplant Surgeon` (hyphens not even converted to spaces) |
| Beard | `beard-transplant - Dr Rana Irfan - Hair Transplant Surgeon` |
| Eyebrow | `eyebrow-transplant - Dr Rana Irfan - Hair Transplant Surgeon` |
| Female Hair Loss | `female-hair-losses - Dr Rana Irfan - Hair Transplant Surgeon` |
| FAQ | `faq - Dr Rana Irfan - Hair Transplant Surgeon` |

This reads like a Rank Math/Elementor title-template field pulling the raw
post slug instead of the formatted post title — consistent across every
page touched by the redesign, and absent on the two pages the redesign
didn't touch (Contact's title, `Dr Rana Irfan Contact Number and
Bookings`, is normal). Title tags are a primary ranking and CTR signal;
this is a **new critical, site-wide issue**, not a cosmetic one — logging
it as a new row below.

Everything found in the earlier same-day regression check (`OP-06`,
`OP-22`, `TECH-21` — the homepage's duplicated title, weakened H1, and 22+
malformed HTML tags) is **still present, unchanged**, confirmed again on
this crawl.

## 4. Unaffected pages

- `/contact/` — not touched, no new issues, title/H-tag structure fine.
- `/blog/` (index) — not touched by this redesign, but has its own
  pre-existing issue worth a new line: the page's `htags` extraction shows
  **9 H1 tags**, one per listed post card, instead of one page H1. A
  listing page should use H1 once (for the page itself) and H2/H3 for each
  post card's title — logging this as a new minor finding, not part of
  the redesign.
- `/ifi-hair-transplant/` — still 404. `OP-10`'s "no dedicated IFI page"
  finding stands unchanged despite the clinic's own content team clearly
  having the material (IFI is named repeatedly across the redesigned
  pages) to build one.

## 5. Search Console check — any measurable impact yet?

Checked the last 30 days by day, then the Oct 1–22 window by page (via
the URL-prefix property — the domain property is still returning a
provider-side error on every query, consistent with `TECH-08`'s
unresolved verification gap).

- **No redesign-attributable swing yet** — GSC data lags a few days, and
  the redesign (Oct 22–23) is too recent for its own effect to show up
  cleanly in what's available. Worth re-checking in 5–7 days.
- **`OP-03`'s zero-click pattern is confirmed still active, at real
  scale**: in just the Oct 1–22 window, `/best-haircuts-for-thin-hair/`
  drew 25,162 impressions for 29 clicks (0.12% CTR) at an excellent
  average position of 4.8; `/how-to-stop-hair-growth-on-moles/` drew
  24,095 impressions for 20 clicks (0.08% CTR) at position 2.3.
  Both numbers are in the same range as `OP-03`'s original baseline
  evidence, not a new escalation — this is the same known pattern,
  reconfirmed with fresher numbers. Updating `OP-03`'s row with this.
- **Homepage**, same window: 3,513 impressions, 124 clicks, **3.5% CTR**
  (healthy) but average position **18.55** — consistent with `OP-05`'s
  framing (decent engagement once seen, but not ranking competitively for
  the money keywords).
